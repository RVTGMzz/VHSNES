## Purpose

### Length expansion: what *is* actually available?

Of the 102 source labels, 11 have native single-byte ASCII spaces immediately after the Japanese glyph text. Four such entries (`0x31E50`, `0x31E7B`, `0x32874`, `0x33050`) overlap earlier translated physical regions and **must not** be edited independently. The remaining seven are:

- The existing six **UNAPPROVED** padding experiments at `0x338D8`, `0x338F7`, `0x33AC5`, `0x33C27`, `0x33C3E`, `0x33C55` (checkpoint 062).
- One more, `0x34245`, has only 2 trailing ASCII bytes, enough for one extra V2 glyph: 3 original glyphs → at most 4, still too short for **Hanawa Akira**. Do not count it as solved.

The other **75 independent fields have zero spare trailing ASCII bytes** and need correctly sized short options or genuine script/pointer relocation, not unsafe blind padding overwrite.

### Potential relocated-text storage; NOT approved

There is an exact **5,881-byte run of `0xFF`** at ROM offsets `0x36907` through `0x37FFF` (end-exclusive `0x38000`). This is physical bank padding next to the Quiz data, **not proof of writable free storage**. We have not identified an authoritatively grounded script pointer table or game interpreter redirect for these fields. A naive search for some 16/24-bit LoROM addresses did not establish a reproducible pointer mapping. No bytes were patched or used at these addresses.

To make a real expansion patch, first identify the game's text interpreter and entrypoint/reference mechanism, demonstrate control-flow safely returning after a longer string, verify a relocated sample in an emulator and test answer highlight/navigation. Avoid treating `0xFF` alone as permission to overwrite executable or referenceable space.
